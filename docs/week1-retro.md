# Ретро недели 1 — черновик для команды

> Фактическая часть заполнена по git, решениям и экспериментам. Блок
> «решить командой» нельзя считать общим решением до короткого созвона/подтверждения.

## Что получилось

- Сквозной ROS 2/Gazebo контур появился раньше календаря и теперь защищён e2e CI.
- Все 11 товаров вошли в seeded-матрицу; причины ошибок отделяются от голого PASS.
- Шибер выбран по данным и исправлен после инструментальной проверки сустава:
  повтор 6/6 дал на box_400 81.849 против 331.085 м/с² у толкателя (мягче в 4.0×).
- Контракты ROS, перепланирование, E-stop и безопасность закреплены тестами.
- Отрицательные результаты сохранены: широкая лента не помогла и ухудшила удар.
- Найден системный дефект origin спавна; box_400 после исправления прошёл 3/3.
- Обнаружен скрытый дефект шибера: лопасть пересекала ленту и не возвращалась;
  старые headline-метрики 62.3/381 и census 26/33 помечены как нефинальные.

## Что мешало

- «Seed» ошибочно воспринимался как детерминизм всей физики: одинаковые сцены
  расходились на ±2–3 ячейки из-за контактов Gazebo.
- Исправления симптомов порождали новые симптомы: height/2 → 20 мм → 5 мм, пока
  не проверили реальный pivot сетки.
- Обрезанный stdout давал ложный `no_fire`; финальная поза важнее наличия строки.
- Долгие census запускались до дешёвого replay одной проблемной ячейки.
- Параллельная работа иногда приводила к одинаковым локальным исправлениям и
  гонке push; частый fetch и маленькие коммиты предотвратили потерю истории.
- Чистый checkout не содержит закрытые STL, поэтому CI потребовал текстовый fixture.

## Что менять в процессе

1. Перед гипотезой печатать исходные числа/позу; затем менять одну переменную.
2. Сначала unit/geometry lock и одиночный replay, затем 3 позы, только потом 33.
3. Метрика вехи — минимум два одинаковых полных прогона + triage причин.
4. Перед началом задачи — fetch и короткая запись владельца/файлов; перед push —
   повторный fetch. Совпавшие исправления не мержить механически.
5. Эксперимент считается завершённым только со строкой в `experiments.md`.
6. Порог/правило нельзя менять по синтетике без реального Gazebo-кадра.

## Технические решения на вход недели 2

- Продуктовый механизм один: шибер со склизом; толкатель — baseline.
- Следующий опасный рефактор — multi-item, его делаем до CV/ML-полировки.
- Категория остаётся формальным правилом; ML допустим для локализации/сегментации.
- E-stop функциональный, но не safety-rated аппаратная система.
- Два census после исправлений дали стабильный диапазон 30–30/33; три остаточных
  дефекта повторились по тем же ячейкам и причинам.
