# Расчёт угла склиза (компенсация допущения `mu=0.05`)

> Закрывает строку 1 слайда `docs/defense/physics_oneslide.md`. Цифровая модель
> кладёт товар на **плоский** пол зон C/D с трением `mu=0.05` (полированный лоток),
> иначе первый товар застревает у устья и следующий ложится на него вне зоны
> (`docs/report/physics_assumptions.md`, `decisions.md` 2026-07-17). На реальной
> чёрной ткани/картоне/плёнке `mu ≈ 0.3–0.5`, и на плоском полу товар встанет.
> Инженерный ответ: плоский пол заменяется **наклонным склизом** — тогда сход
> гарантируется геометрией, а не подобранным коэффициентом.

## Условие схода (когда товар не застревает)

Товар на склизе под углом `β` к горизонту едет вниз, если скатывающая
составляющая силы тяжести превышает трение покоя:

```
m·g·sin β  >  mu · m·g·cos β
⇒  tan β  >  mu
⇒  β  >  arctan(mu)
```

Масса сокращается — **условие схода от массы товара не зависит** (важно: массы у нас
назначены командой, `physics_assumptions.md`; здесь они не входят в ответ вовсе).

| Ожидаемое трение `mu` | Материал пары контакта | `arctan(mu)` = минимальный угол |
|---:|---|---:|
| 0.3 | гладкий картон / плёнка по стали | 16.7° |
| 0.4 | ткань по крашеной стали | 21.8° |
| 0.5 | техническая ткань по пластику | 26.6° |
| 0.7 | грязный/влажный контакт (пессимизм) | 35.0° |

**Проектный угол `β = 35–40°`.** При `β = 40°` условие схода держится вплоть до
`mu = tan 40° = 0.84` — то есть с запасом перекрывает не только ожидаемые 0.3–0.5,
но и деградировавший грязный/влажный контакт. Это переводит `mu=0.05` симуляции из
«костыля решателя» в проверяемое **проектное требование к геометрии склиза**.

## Скорость товара внизу склиза (заодно закрывает удар приземления)

Строка 5 того же слайда: в симуляции сход в клетку — свободное падение с кромки
ленты `h = 0.40 м`, дающее `v = √(2gh) = 2.80 м/с` о дно (риск брака хрупкого
товара). Наклонный склиз с малым вертикальным перепадом `h_склиз` заменяет удар
скольжением. По энергии на склизе длиной `L = h_склиз / sin β` с ускорением
`a = g(sin β − mu·cos β)`:

```
v_низ² = 2·a·L = 2·g·h_склиз·(1 − mu·cot β)
```

Для проектного склиза `β = 40°`, перепад `h_склиз = 0.10 м` (строка 5: съезд
<10 см), пессимистичный `mu = 0.4`:

```
1 − 0.4·cot 40° = 1 − 0.4·1.19 = 0.524
v_низ = √(2·9.81·0.10·0.524) = √1.028 = 1.01 м/с
```

**Итог: 1.0 м/с скольжения вместо 2.8 м/с падения** — пик приземления, который в
симуляции доминирует над всей бережностью (`calc_vs_sim.md` якорь 4), режется
геометрией склиза в ~2.8× по скорости и ~7.8× по кинетической энергии удара, без
единой правки логики или таймингов.

## Что этот расчёт НЕ доказывает (честная граница)

- `mu` реальной пары контакта **не измерен** — взят диапазон 0.3–0.5 из справочных
  значений похожих материалов; перед изготовлением нужен прямой замер трения на
  образце ленты/склиза (DOE, `physics_assumptions.md`).
- Расчёт статический (порог схода) и энергетический (скорость внизу); он не
  моделирует кувырок несимметричного товара, застревание углом или упругий отскок.
  Это проверяется на макете склиза, а не выводится формулой.
- Выбор `β = 40°` оставляет запас именно для того, чтобы поглотить эти
  неучтённые эффекты и разброс `mu`; он не оптимизирован под минимальную высоту
  участка.
