Механизм маршрутизации

Шибер, а не толкатель

ПочемуБережность, измеренная в числах

  • Товар уходит со скоростью ленты — нет бокового удара 2,5 м/с
  • На тяжёлом коробе шибер ≥1,3× мягче по пиковому ускорению, точечно до 3×
  • Движущаяся лента сама сводит товар вдоль стенки к кромке

ЦиклПолный ход механизма

  • Сигнал классификатора → стенка формируется за 0,5 с до входа
  • Смена зоны требует расчётных 3,1 м «воздуха» — планировщик отвергает опасный поток до старта
  • Склиз → зона → возврат; E-stop с восстановлением, разделение зон

СтекЧто и почему

  • Python 3.11 · ROS 2 Humble · Gazebo Fortress — из разрешённого списка, разворачивается на стенде организаторов
  • Классический CV, без нейросети. Усложнение обязано побить бейзлайн числом — а бить нечего: 33/33
  • NumPy / SciPy — геометрия сечений и K считаются векторно

ПроверкаРазвернётся у вас

  • Одна команда: чистый checkout → пиннутый Docker → headless CPU e2e
  • Один seed задаёт эпизод однозначно — прогон повторяется дословно
  • Эксперт меняет входные параметры и смотрит поведение: сценарии в README

Ограничения и развитие09
Где решение упрощает мир

Что мы знаем
про свои границы

ГраницыНазваны прямо

  • 10 шт/мин — sustained, 18 — пиковый короткий поток. За заявку выдаём меньшую цифру
  • Плотный same-zone поток деградирует: один эпизод из шести даёт 2/6 (в сумме 29/33) — три товара сходят с ленты влево. Классификация в них верна, отказ исполнительный. Воспроизведён дважды, полную причину не нашли; зазор 1,0→1,8 м поднимает до 3/6
  • Физика — инженерные допущения: массы, ODE-трение, rigid-body
  • Прототип — осознанный NO-GO: постановка допускает ПАК в симуляции

ДальшеЧто делаем следующим

  • DOE по физике перед изготовлением — развести допущения и реальность до металла
  • Склиз и рампа для мягкости приземления в зоне
  • Поток «не уверен» на низкой confidence вместо тихо неверного ответа
