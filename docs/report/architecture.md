## Схема

```
Gazebo (sim/worlds/cell.sdf)                          ROS 2 (launch/skeleton.launch.py)
┌─────────────────────────────────┐
│ лента (призм. джойнт, 1 м/с)    │◄── /conveyor/cmd_vel ──┐
│ направляющие подачи (x −6..0.7) │                        │
│ RGBD-камера 15 Гц (x=1.5, вниз) │── camera, /clock ──► ros_gz_bridge (sim/bridge.yaml)
│ толкатель C (x=2.5, выброс +y)  │◄── /pusher_c/cmd ──┐   │
│ толкатель D (x=3.0, выброс −y)  │◄── /pusher_d/cmd ──┤   │
│ зоны B / C / D                  │                    │   │
└─────────────────────────────────┘                    │   │
                                                       │   │
  /camera/depth_image + /camera/camera_info            │   │
        │                                              │   │
        ▼                                              │   │
  perception_node ── /item/measurement ──► classifier_node │
  (габариты мм, K,    (ItemMeasurement)    (правила из src/ │
   позиция в мире)                          classification) │
                                               │           │
                                               ▼           │
                        /item/classification (ItemClassification)
                                               │           │
                                               ▼           │
                                        controller_node ───┘
                                        (мягкий пуск ленты,
                                         dead-reckoning, толкатели)
```

## Узлы и контракты

| Узел | Вход | Выход | Суть |
|---|---|---|---|
| `ros_gz_bridge` | топики Gazebo | топики ROS 2 | камера, `/clock`, команды ленты и толкателей (`sim/bridge.yaml`) |
| `perception_node` (`src/perception.py`) | depth-кадр 15 Гц | по одному `ItemMeasurement` на товар | связные depth-компоненты измеряются независимо; nearest-neighbour tracker сохраняет `item_id` между кадрами; геометрия даёт габариты, K и мировую позицию, частично видимые компоненты отбрасываются |
| `classifier_node` (`src/classifier_node.py`) | `ItemMeasurement` | `ItemClassification` | правила задачи (пороги 10×10×10 и 450×320×320 мм, K > 0.8) из `src/constants.py` — единственного источника доменных констант |
| `controller_node` (`src/controller_node.py`) | `ItemClassification`, `/emergency_stop` (`Bool`) | `/conveyor/cmd_vel`, `/pusher_{c,d}/cmd` | мягкий пуск ленты; B — едет до конца, C/D — команда механизму по dead-reckoning; защёлкнутый E-stop отменяет таймеры и обнуляет все приводы |

Контракты — типизированные сообщения `ros_msgs/` (`ItemMeasurement` без
категории, `ItemClassification` с категорией): владение полями явное,
perception и классификатор разрабатывались независимо против моков.

## Ключевые решения (подробно — decisions.md)

- **Единое время.** Все узлы на `use_sim_time`: штампы камеры — sim-время
  Gazebo, таймер выстрела считает на тех же часах. Санити-проверка отбрасывает
  измерения старше секунды — смешение wall/sim часов иначе ломает контур молча.
- **Перепланирование выстрела.** Dead-reckoning предполагает постоянную
  скорость ленты, что неверно на разгонной рампе. План выстрела обновляется
  каждой свежей классификацией (15 Гц) до момента выстрела — последнее
  измерение снято на полной скорости и самокорректирует ранние.
- **Геометрия удержания.** Высокие направляющие на участке подачи (вне окна
  камеры) гасят раскачку круглых товаров на рампе; к камере товар приходит
  устоявшимся. Окно камеры и пути выброса толкателей свободны.
- **Толкатели разнесены по x.** Лицом к лицу на одном x паркованная лопатка
  перегораживает чужой путь выброса (проверено экспериментом дня 2).

## Воспроизводимость и проверка

Сквозной прогон — одна команда, без ручных вмешательств:

```
bash scripts/run_skeleton.sh <товар> <B|C|D>   # спавн → контур → проверка зоны
```

Спавн детерминирован (x=−1.5, штатная ориентация STL); случайность появится
на дне 4 (случайные ориентации через явный seed). Прогоны дня 3: Короб 300 → B,
Короб 400 → C, Тарелка → D, Шлем → B (3/3) — все PASS, цикл ~24 с от старта
launch (см. experiments.md).

Иллюстрации: `img/day1_camera_rgb.png` (что видит камера),
`img/day2_perception_overlay.png` (габариты и K поверх depth-кадра).
Видео сквозного прогона (Тарелка → D) снимается одной командой
`bash scripts/record_skeleton_video.sh plate D` — камера-«зритель»
подсаживается в мир только на время записи; mp4 в репозиторий не кладём
(GIT.md), файл уходит в облако организаторов.
