# Безопасность эксплуатации

## E-stop

Контроллер принимает защёлкиваемую команду `std_msgs/Bool` на
`/emergency_stop`.

- `True` немедленно отменяет разгон и все отложенные срабатывания, очищает
  очередь маршрутизации и публикует `0.0` на ленту, шибер C и шибер D.
- Повторный `True` ничего не меняет: остановка остаётся активной.
- Только явный `False` снимает блокировку. После сброса лента проходит обычный
  восьмишаговый мягкий пуск; старые классификации не исполняются.
- Обработчики разгона, классификации, срабатывания и возврата дополнительно
  проверяют состояние E-stop, поэтому уже проснувшийся callback не возобновит
  движение.

Ручная команда:

```bash
ros2 topic pub --once /emergency_stop std_msgs/msg/Bool "{data: true}"
# осмотреть и освободить рабочую зону, затем:
ros2 topic pub --once /emergency_stop std_msgs/msg/Bool "{data: false}"
```

## Проверка в симуляторе

```bash
bash scripts/smoke_estop.sh
```

Smoke запускает финальный мир шибера, дожидается измеренного движения товара,
посылает E-stop и одновременно проверяет нулевые команды всех трёх приводов.
Контрольный прогон 12.07: до остановки `dx=0.036 м / 1.0 с` (RTF headless
Gazebo ниже единицы), после установления остановки `dx=0.000 м / 1.2 с`;
результат PASS. Порог движения в тесте — `>0.03 м`, остаточного движения после
короткого выбега — `<0.05 м`.

Отдельный node-тест фиксирует более опасный сценарий: запланированный будущий
выстрел отменяется, новые классификации во время блокировки игнорируются, а
после `False` скорость не прыгает сразу к 1 м/с.

## Разметка зон

Оба мира (`cell.sdf` и `cell_diverter.sdf`) содержат одинаковую
visual-only модель `safety_marking`, которая не меняет столкновения и физику:

- красный периметр `x=-1.5..4.5, y=-1.55..1.55` охватывает движущуюся ленту,
  камеру, механизмы и места приземления товаров — присутствие оператора внутри
  при работе запрещено;
- зелёная полоса `y=1.95..2.65` обозначает операторский проход за периметром.

Геометрия и отсутствие collision у разметки закреплены XML-тестами для обоих
миров.

## Граница применимости

Это функциональный E-stop цифрового прототипа, а не сертифицированная функция
безопасности. Он зависит от живого ROS 2-контроллера, DDS и программного
JointController, не имеет аппаратного размыкания энергии, резервирования,
контроля залипания контакторов и safety-rated PLC. Для физической установки
нужны оценка рисков, ограждение/блокировки, аппаратная кнопка с контролируемым
сбросом и независимое снятие энергии с приводов по применимым нормам. Сброс
команды не означает автоматическое разрешение персоналу входить в красную зону.
