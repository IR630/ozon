# Видео-вставки (сырьё для монтажа H2)

Готовые полноэкранные графики для видеодемонстрации (`../../video_script.md`).
Формат **1920×1080**. Для каждой — `*.svg` (источник: правится текстом, легко
перекрасить/поправить подпись) и `*.png` (готово бросить в таймлайн редактора).
Все числа сверены с пакетом на 2026-07-30 (`final_report.md`/`calc_vs_sim.md`/`soak.md`);
строка производительности — по ОТГРУЖАЕМОЙ ДВУХкамерной стойке, а не по лучшей.
**Правка 30.07:** карточка показывала `8 шт/мин · 3 головки` и `0.030 с` — заявку
трёхкамерной стойки и синхронизацию одноголовой, то есть в кадр уезжали числа
двух стоек, которых не существует в отчёте. Приведено к отгружаемой: `9 шт/мин ·
2 головки`, `0.042 с`.

| Файл | Сегмент сценария | Что показывает |
|---|---|---|
| `metrics_card.*` | 7 (Подтверждение числом) | «Доказано числом»: census 33/33, 163/165, 9 шт/мин (2 головки), 0.042 с, бережность, УГТ 4 |
| `sync_timeline.*` | 4 (демо / синхронизация) | «Упреждение работает с запасом»: транзит 1.75 с = решение 0.33 + запас 0.92 + упреждение 0.5. **`0.33 с` — это набор 5 кадров при 15 Гц, а НЕ latency камера→решение (медиана 0.042 с);** подпись на графике теперь говорит это прямо, иначе два числа читаются как противоречие |

Оверлей depth-кадра (сегмент 3) отдельным файлом не делаем — берётся существующий
`../../img/day9_overlay_ids_state.png` (маска, id, dims/K на реальном кадре).

## Перерендер после правки SVG

```bash
python scripts/render_inserts.py     # обе вставки разом, Chromium из playwright
```

Прежняя инструкция звала `rsvg-convert`, которого нет ни в одной среде проекта —
поэтому PNG и разъехался с SVG: карточка метрик показывала снятую заявку
«10 шт/мин», когда документы вокруг уже говорили другое. Правишь SVG — сразу
гони эту команду, иначе в монтаж уедет старый PNG.
