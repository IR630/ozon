# Решение за 3 минуты — трек 3, роботизированная пресортировка

> Одностраничное резюме для быстрого входа. Итоговый отчёт — `final_report.md`,
> навигация — `README.md`, карта критериев → артефакт — `criteria_coverage.md`.

## Задача
Виртуальная ячейка пресортировки: depth-камера над непрерывно идущим конвейером
(1 м/с) видит товары, классифицирует каждый и физически раскладывает по зонам:
**B** — подходит для основного сортировщика; **C** — не проходит по габаритам
(строго вне 10×10×10 … 450×320×320 мм); **D** — круг в сечении (K > 0.8), нужна доупаковка.

## Как устроено (единый контур, не два компонента)
```
подача → depth-камера → перцепция (item_id, габариты, K) → классификатор (B/C/D)
       → контроллер (упреждающий тайминг) → поворотный шибер → склиз → зона
```
Всё замкнуто в Gazebo (ROS 2 Humble + Fortress); ядро перцепции/классификации
тестируется отдельно от ROS. Механизм — сменный мир, а не ветка кода.

## Ключевые инженерные решения
- **Только depth, без цвета:** классификация работает по геометрии глубины и не
  читает RGB → инвариантна к окраске товара по построению (организаторы на QA
  18.07 подтвердили: палитра произвольна — наше решение устойчиво без правок).
- **K по проекциям:** максимум из верхнего силуэта и восстановленной торцевой
  проекции — закрывает «круг в любом сечении» (лежащая Бутылка → D), согласуется
  с ответом организаторов «K смотреть по проекции».
- **Шибер вместо толкателя:** товар идёт со скоростью ленты (нет удара 2.5 м/с),
  движущаяся лента сама сводит его вдоль стенки к кромке. Выбор доказан числом
  бережности, не «на вкус».
- **Упреждение:** стенка формируется за 0.5 с до входа товара; смена зоны требует
  расчётных 3.1 м «воздуха» (HOLD+RETRACT) — планировщик отвергает опасный поток
  до старта Gazebo.
- **Безопасность:** в v0.5 подтверждены E-stop/freeze и базовое восстановление,
  разделение рабочих/безопасных зон и прозрачные бортики камерной секции.
  Feedback-gated reset занятого шибера (Stage 26) влит в ядро 21.07: physical
  occupied gate закрыт, resource/latency-gate на окружении организаторов открыт.

## Честные границы (в отчёте раскрыты)
- **10 шт/мин — sustained; 18 — пиковый короткий поток**, не выдаётся за устойчивый.
  Плотный 6-товарный same-zone поток деградирует (насыщение хода ленты).
- Физика: массы, ODE-трение, rigid-body — инженерные допущения
  (`physics_assumptions.md`); реальная ткань/привод не моделируются.
- Физический прототип — NO-GO (осознанно, целостный ПАК в симуляции по условию).

## Воспроизводимость
Вся случайность — через один seed; тройка `(seed, item_index, orient_index)`
задаёт эпизод однозначно. Развёртывание как у организаторов — одной командой:
`scripts/check_clean_deploy.sh` (чистый checkout → пиннутый образ → headless CPU
e2e). Таблица «заявка → команда» — в `README.md`.

## УГТ (самооценка)
**CV 4 × исполнение 4** — исполнение 4 обосновано сведением расчёт↔симуляция
(`calc_vs_sim.md`); финальный балл подтверждается командой на сверке перед защитой.
