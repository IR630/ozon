## Прочитай это до того, как начнёшь

Твоя ветка стартует **проигрывая** по метрике, за которую начисляют баллы.
Измерено на 165 позах при типичной калибровке 2 мм·0,2° (union-слияние):

| | мисроуты | допуск |
|---|---|---|
| 1 камера | 8,0 | 47 % |
| 2 камеры | **2,3** | 81 % |
| 3 встречные | 8,0 | **95 %** |

Три головки — лучшие по точности измерения и худшие по маршрутизации.
Это не шум, механизм известен: габарит есть **экстремальная статистика** (максимум
по головкам), каждая головка вносит независимую ошибку регистрации, максимум из N
розыгрышей растёт с N. Медиана тончайшего габарита Ручки: 9,0 → 9,4 → **10,2** мм
при одной / двух / трёх головках, порог 10,0 мм. Систематика, не невезение.

**Поэтому твоя ветка — не «версия получше». Это проверка гипотезы: можно ли забрать
95 % точности, не заплатив восемью мисроутами.** Если да — ветка выигрывает
и берётся в решение. Если нет — закрывается как честный отрицательный результат.
Второй исход нормален и заранее заложен; подгонять метрику под результат нельзя.

## Настоящая работа ветки — §4 плана

Наивный union третью головку не оправдывает. Экономь время на уже оплаченном:

**Не сработало, повторно не тратить:**
- **ICP-регистрация облаков.** Стало хуже: превышения порога 53 % → 64 %, максимум
  12,5 → 16,3 мм. Ортогональные виды тонкого тела почти не перекрываются, ICP
  не за что зацепиться, выравнивание уплывает. Отрицательный результат уже получен.

**Сработало, но меняет расклад:**
- **Структурное слияние** (след XY только с верхней головки, боковые дают лишь
  скрытую вертикаль): мисроуты 8,0 → **1,0 при ОДНОЙ камере**, 3,7 при двух и трёх,
  допуск ровно 80 % при любом числе головок. То есть оно снимает штраф лишних
  головок и **вместе с ним обнуляет их выигрыш** по точности.

Отсюда задача: схема слияния, берущая 95 % точности, не платя маршрутизацией.
Кандидаты по возрастанию цены:

1. **Медиана вместо максимума** по головкам — бьёт прямо в механизм экстремальной
   статистики. Самый дешёвый и самый точный по диагнозу. **Начинай с него.**
2. Структурный след + боковые допущены к габариту только там, где верхняя головка
   признаёт себя неуверенной (высокий рельеф, наклонное тело).
3. Явный поток «не уверен» на габаритах в пределах ошибки калибровки от порога.
   Ручку это не починит, но переведёт тихий неверный вердикт в честный —
   по CLAUDE.md (Карпаты #6) это и есть правильное поведение.

## Три вещи, на которых твоя ветка провалится незаметно

1. **Рассинхрон кадров** — до 66,7 мс → **66,7 мм** пробега при 1 м/с, против
   допуска 5 мм. У тебя три несинхронных потока вместо двух, штраф втройне.
   Без компенсации по метке времени все числа ветки недействительны.
2. **Два корпуса в кадре верхней головки.** Обе стойки на `y = ±0.90` внутри её
   конуса на уровне ленты. Попадут в маску — `_find_item` вернёт `None` на каждом
   кадре (блокер дня 5). **Отрендери и посмотри глазами до любого кода** (Карпаты #1).
3. **`max(K)` по видам.** Не делай. Боковые ракурсы видят торцевой круг у всего
   лежащего и погонят товары в D. K остаётся top-only, ветка меняет только габариты.
