# Перемер 29.07: что запускать на машине с Gazebo

Сдача 30.07. Этот лист — то, что нельзя посчитать без ROS 2 + Gazebo, с точными
командами. Всё, что считается без них, уже посчитано и записано в разделе 3.

Запускать в WSL Ubuntu-22.04 (Fortress + Humble), из отдельного worktree, чтобы
правки в основном дереве не портили прогон на ходу.

---

## 1. Пропускная способность 1 / 2 / 3 головок — ГЛАВНОЕ

Числа `9 / 5 / 6 товаров/мин` сняты одним заходом на одном ядре и **немонотонны**:
две головки не могут быть медленнее трёх, когда кадр 51 против 72 мс,
transit+verdict 11,2 против 15,2 с и bringup 28,7 против 38,0 с монотонны.
Пока это не перемерено, число `5` публиковать нельзя.

Бюджеты харнесса обязательны: при дефолтных 30 с трёхголовая стойка не успевает
подняться (bringup 40,3 с) и даёт 100 % `ABORT: belt never reached full speed`.

```bash
cd ~/Ozon-c2 && git fetch origin && git checkout main && git pull --ff-only

# 1 головка
for s in 0 1 2; do
  WORLD=sim/worlds/cell_diverter.sdf BRIDGE_CONFIG=bridge.yaml \
  LOGDIR=runs/thr1_seed$s bash scripts/run_stream_suite.sh $s 0 2
done

# 2 головки
for s in 0 1 2; do
  WORLD=sim/worlds/cell_diverter_2cam.sdf BRIDGE_CONFIG=bridge_2cam.yaml \
  SOFT_START_TRIES=240 EPISODE_TIMEOUT=400 \
  LOGDIR=runs/thr2_seed$s bash scripts/run_stream_suite.sh $s 0 2
done

# 3 головки
for s in 0 1 2; do
  WORLD=sim/worlds/cell_diverter_3cam.sdf BRIDGE_CONFIG=bridge_3cam.yaml \
  SOFT_START_TRIES=240 EPISODE_TIMEOUT=400 \
  LOGDIR=runs/thr3_seed$s bash scripts/run_stream_suite.sh $s 0 2
done

python3 scripts/measure_throughput.py runs/thr1_seed* runs/thr2_seed* runs/thr3_seed*
```

**Что записать:** медиану и разброс по seed для каждой стойки, число
неразрешимых интервалов (`unresolved`), и подтверждение `heads=N` в логах —
иначе прогон мерил не ту стойку.

**Если немонотонность воспроизведётся** — это не свойство стойки, а дефект
замера или загрузка машины: гнать на незагруженной, как уже приходилось делать
с `bottle oi=1` и `lunchbox oi=2`.

## 2. Мульти-seed отгружаемой стойки — только если остаёмся на трёх

`163/165` снят на ОДНОЙ головке (`runs/census2cam_seed0..4` подтверждает две).
**У трёх головок мульти-seed не мерян вообще.** Если прод остаётся трёхкамерным,
главное число отчёта описывает не ту конфигурацию, которая отгружается.

```bash
for s in 0 1 2 3 4; do
  WORLD=sim/worlds/cell_diverter_3cam.sdf BRIDGE_CONFIG=bridge_3cam.yaml \
  SOFT_START_TRIES=240 CELL_TIMEOUT=400 \
  LOGDIR=runs/census3cam_seed$s bash scripts/run_matrix.sh $s 3
done
python3 scripts/census_seed_sweep.py runs/census3cam_seed*
```

Порядка 5 часов. По T2 результат не может превысить `163/165` — но «не может
превысить» и «измерено» это разные ответы, когда спрашивает жюри.

## 4. Рассогласование конфигурации — чинится без прогонов

Найдено 29.07 чтением кода. Прогонов не требует, но требует решения.

| Место | Что стоит | Сколько камер |
|---|---|---|
| `README.md:37` | «Отгружаемая конфигурация — трёхкамерная стойка» | 3 |
| `README.md:124` | `WORLD=sim/worlds/cell_diverter.sdf run_skeleton.sh` | **1** |
| `README.md:124` (следующая строка) | `bash scripts/run_stream.sh` без `WORLD` | **3** (дефолт `run_stream.sh:43`) |
| `README.md:277, 283, 321, 334` | воспроизведение `33/33` и `163/165` на `cell_diverter.sdf` | **1** |
| `launch/skeleton.launch.py:43` | дефолт `BRIDGE_CONFIG=bridge_3cam.yaml` | 3 |
| `scripts/run_skeleton.sh:85` | дефолт `WORLD=cell.sdf` | **1** |
| `scripts/ci_e2e.sh:14-15` | явно 3cam + бюджеты | 3 (честно) |

Сенсоров в мирах: `cell.sdf` 1, `cell_diverter.sdf` 1, `cell_diverter_2cam.sdf` 2,
`cell_diverter_3cam.sdf` 3.

**Три следствия.**

1. Дефолтный запуск `bash scripts/run_skeleton.sh <slug> <зона>` без переменных
   даёт **несогласованную пару**: одноголовый мир `cell.sdf` с трёхголовым
   мостом. Падения нет — боковые топики просто не публикуются, и слияние
   деградирует к верхней головке бит-в-бит (`src/multiview.py:116-121`). То есть
   «три камеры» в этом пути номинальны, а не фактические.
2. Две соседние команды в одном блоке README поднимают **разные стойки**, и это
   нигде не сказано.
3. Команды, которыми жюри воспроизводит заявленные `33/33` и `163/165`,
   запускают одноголовую стойку — что верно по происхождению чисел и
   противоречит заявлению строки 37.

Гейт деплоя при этом честен: `ci_e2e.sh` явно экспортирует трёхкамерный мир,
трёхкамерный мост и поднятые бюджеты, поэтому `heads=3` в e2e-логе — настоящий.

**Чинится выбором одной конфигурации и приведением к ней всех семи мест.**
Единственная стойка, у которой ВСЕ заявленные числа сняты на ней самой, —
одноголовая: `33/33`, `163/165`, `9 товаров/мин`, `32 мс` в такте `66,7 мс`.
У двух головок есть измеренный мульти-seed `163/165` и такт соблюдён (`51 мс`),
но пропускная у них — то самое неперемеренное `5`. У трёх нет мульти-seed, и
`72 мс` не влезают в такт при 15 Гц.
