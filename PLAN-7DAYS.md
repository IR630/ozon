## День 1 — среда и фундамент

Решения на синке дня 1 (→ `docs/decisions.md`):
1. Версии: рекомендация **ROS 2 Humble + Gazebo Fortress** (LTS-пара,
   максимум материалов); альтернатива Jazzy + Harmonic.
2. Контракт CV → контроллер: custom msg `ItemClassification`
   (id, category B/C/D, dims_mm[3], k, confidence, position, stamp).
   Владелец — P1, изменения только через PR.
3. Массы товаров (в STL их нет): назначить по здравому смыслу, записать таблицей.

| Кто | Задача | Артефакт | Критерий готовности |
|---|---|---|---|
| P1 | Docker-образ ROS 2 + Gazebo + ros_gz, docker compose, инструкция; CI-джоб colcon build | `docker/`, README-раздел | Каждый из 5 запускает контейнер и видит пустой мир Gazebo |
| P2 | Мир участка 6×10 м: лента A (движение поверхности 1 м/с), зоны B/C/D | `sim/worlds/cell.sdf` | Короб 300 спавнится и едет по ленте с корректной скоростью |
| P3 | RGB+depth камера над лентой, мост топиков ros_gz, дамп кадров | `sim/models/camera/`, скрипт дампа | PNG с камеры с товаром на ленте в репозитории |
| P4 | `src/constants.py`, порт `classify()` из scripts, msg-пакет контракта, тесты | `src/`, `ros_msgs/` | `pytest -q` зелёный, существующие 11 тестов не сломаны |
| P5 | STL → SDF: 11 товаров, децимация тяжёлых (Шлем, Мешок), convex-коллизии, массы | `sim/models/items/` | Все 11 загружаются в gz, отрендерены и просмотрены глазами (принцип Карпаты №1) |

Зависимости: P2/P3/P5 работают в чистом Gazebo до готовности Docker-образа P1;
P4 не зависит ни от кого.

## Чему следуем (CLAUDE.md)

Overfit a single batch: дни 1–3 — про ОДИН товар end-to-end, 11 товаров — день 4+.
Решения — по данным, не по вкусу (день 5 существует ради дня 6). Baseline прежде
нейросети: неделя 1 целиком классическая, сеть недели 2 обязана побить её числом.
Визуализация на каждом этапе. Всё через seed. Тесты в том же коммите.
День 7 — техдолг, а не фичи: качество фундамента — потолок решения.
